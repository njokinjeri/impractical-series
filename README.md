# Impractical Series

A collection of intentionally non-essential builds. Each project starts with a vague idea and evolves through experimentation, preserving the original visual or conceptual intent as much as possible, with room to pivot only when reality pushes back.

## Philosophy

Each project is a visual question. The code is the answer, or part of one.

Every project includes a `LEARNINGS.md` documenting the concept, process, and what it opened up. Each build serves two things simultaneously: technical growth, and the freedom to test ideas that feel premature, impractical, or *not yet reachable* at the time they're built.

Projects are deliberately unplanned. There is no roadmap. Curiosity paves the way.

### Why "Impractical"?

Because not everything worth building needs a reason beyond *"I wondered what would happen if…"*

And what's the point of wondering when you can just dive right in.
